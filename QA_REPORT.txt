GPU / ANIMATION
- WebGL2 execution was verified dynamically in headed Chromium under Xvfb; EXT_color_buffer_float was available and the exact production final compositor/style/mask shaders rendered successfully.
- The production fluid path uses velocity advection, curl, vorticity confinement, divergence, pressure relaxation, pressure-gradient subtraction, dye advection, velocity/dye splats, and a masked final compositor. The complete multi-pass solver was not used as a performance benchmark in this software-GPU environment.
- Desktop initial pressure solve: 24 Jacobi iterations; adaptive range 14–30.
- Laptop initial pressure solve: 21 iterations.
- Mobile initial pressure solve: 16 iterations; adaptive range 10–22.
- Desktop simulation short side: 512px (384px on narrower laptops), long side capped at 900px. Mobile short side: 256px, long side capped at 640px.
- Final render pixel budget is capped at about 2.2M desktop pixels and 650k mobile pixels so high-DPI screens do not multiply GPU load unnecessarily.
- A normal desktop frame begins around 32 full-screen/simulation passes at 24 pressure iterations; active cursor strokes can add up to 16 splat passes in a frame. Mobile begins around 24 passes and can add up to 10 splat passes. Adaptive pressure iterations reduce work when frame time rises.
- Fluid splats are deliberately broad, viscous, persistent, and interpolated between pointer samples so fast movement does not break into disconnected circles.
- The hidden material is distorted by both fluid velocity and local dye gradients, with edge/specular treatment to read more like oil/liquid than a simple blurred blob.
- Animation pauses when the page is hidden.
- JavaScript syntax check passed after the final performance optimization.

IMPORTANT PERFORMANCE LIMIT
- This is the same class of multi-pass GPU fluid technique used for high-end interactive liquid-mask work; it is not Nothin’s proprietary code or data.
- Exact parity with noth.in frame rate, GPU cost, or asset-processing volume cannot be truthfully guaranteed without their private source/assets and identical hardware/browser conditions.
- The software-renderer capture is proof that the WebGL2 path executes, not a meaningful real-hardware FPS benchmark. The build targets smooth current-browser performance and adapts pressure iterations to measured frame time.
